# Contribution Guidelines

See [this guide](https://github.com/sindresorhus/awesome/blob/main/contributing.md) for a how-to tutorial for creating a pull request.

Format:
```
- [name](link) - [description ...][punctuation]
^   ^     ^    ^        ^               ^
│   │     │    │        │               │
│   │     │    │        │               └---- a punctuation (usually ".")
│   │     │    │        └---- A short, crisp description of your project
│   │     │    └---- dash separator ("-")
│   │     └---- link to your project
│   └---- name of your project
└---- dash for the list
```

Ensure your pull request adheres to the following guidelines:
- Projects need to be established. Anything awesome is usually even better after a month of real use, so give yours that month first. A check on your pull request measures this, and passes when either:
  - the project is at least 30 days old, counted from when the repository was created or its first commit, whichever is later, and has commits on at least 5 different days; or
  - the project has at least 50 stars.

  If your project doesn't qualify yet, open the pull request once it does.
- Make sure you put your project in the appropriate category.
- Consider using the [crates.io](https://crates.io) link for libraries and widgets.
- Check your spelling and grammar.
- Make sure your text editor is set to remove trailing whitespace.
- Make an individual pull request for each suggestion.
- If you filed an issue, add the issue number with a [GitHub closing phrase](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/using-keywords-in-issues-and-pull-requests#linking-a-pull-request-to-an-issue), so that the issue gets closed automatically (e.g. `closes #123`).

Thank you for your suggestion! 🧀
